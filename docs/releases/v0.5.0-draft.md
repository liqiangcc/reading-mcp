## Reading

- **Seven v2 tools, short handles.** `open` returns a handle; `browse`, `outline`, `search`, `read`,
  `cite` and `source_view` walk it. Handles look like `d3~9f2c.s12.p4.2`, not like locators, and
  `cite` is the only tool that returns a full `TextLocator` (#196, #202, #203).
- **Sentence-first reading.** `read` returns one sentence per call by default; `unit=paragraph`,
  `max_chars` and `back` widen the step or step back, and a paragraph the splitter cannot break comes
  back whole with `kind=paragraph` (#196, #203, #234).
- **v1 is gone.** The nine v1 tools are deleted, and a deployment that still sets
  `READING_MCP_TOOLS=v1` or `=both` now refuses to start instead of silently serving v2 (#269).
- **Stale handles carry a `retry`.** A stale handle still fails closed with `stale_handle`, but when
  the server can prove where the old text now is, the error carries an executable `retry`
  (`read.retry.from`, `cite`/`outline`/`source_view.retry.at`, `search.retry.doc`). Deleted, changed
  or duplicated text gets no retry, and recovery is lazy — no startup scan (#283).
- **PDF word spacing.** pdfTeX writes justified inter-word glue as negative *real* `TJ` adjustments
  that lopdf 0.44 ignored, so words arrived glued (`economicandfinancialsystems`); a large negative
  adjustment now adds at most one space, cutting glued Latin words by 97.6 % over the 121-paper
  corpus (#276).
- **PDF CJK.** A word-gap space is no longer inserted between two CJK characters, so `中文字` stops
  arriving as `中 文 字` and CJK search keeps matching substrings (#282).
- **PDF sentence boundaries.** Spaced decimals (`0 . 5`), dotted numbering (`2.2. Model`) and
  reference abbreviations (`Phys. Rev. Lett.`, `et al. [13]`) stay inside their sentence (#288,
  #253).
- **PDF guard work.** Fewer clean paragraphs are refused as "coarse": model sizes and units (#237),
  repeated names (#242), a per-sentence verdict in long paragraphs (#251), initials and `et al.`
  (#253), and spaced dot runs that used to become one-character sentences (#235).
- **PDF blocks.** A date now counts once in the bibliographic guard, and a caption over a
  mostly-numeric body becomes a `table` block instead of a run of junk sentences (#287).
- **PDF text that used to be lost.** Text inside Form XObjects and `uniXXXX`-named fonts is read
  (#212), TeX Type 1 fonts without `/ToUnicode` decode through a synthesised map (#245), outline
  sections stop at their headings and a page is never repeated (#257).
- **Image-only PDFs say so.** They answer `ocr_required` with the measured page and character counts
  instead of opening nearly empty, and the hint names the two routes that actually work (#224, #231).
- **`source_view`.** Rendered pages are cached on disk and raster-dominated pages come back as JPEG
  (quality 85); `READING_MCP_SOURCE_VIEW_FORMAT=png` restores PNG-only (#277). Local PDFs are mapped
  in the worker instead of copied (#273), and URL PDFs render from the raw-cache body without a
  network round trip (#275).

## Performance

- **Point queries, no document cache.** Reads hit the SQLite store directly: `DocumentCache` is gone
  and hot readers use light document rows and indexed section rows (#201, #205, #207, #209, #223).
  Per-call read cost stops growing with section count: 1.03× at 20 000 sections against 500, where
  it was 19.6× (gate ≤ 1.3, #223 and #229 §Section scale).
- **Storage layout.** The section tree and body order are indexed rows from one source (#221, #226),
  section locations and the layout are compact (#228, #247), and section text and heavy metadata are
  compressed (#211, #218).
- **Reads no longer queue behind writes.** `READING_MCP_READ_POOL` (default 4) gives read paths their
  own read-only connections: during a large EPUB `open`, `read` p95 went 831.6 → 11.0 ms, and on
  `宋史` `search` p50 went 245.5 → 4.2 ms (#286). `=0` restores the old behaviour exactly.
- **Search scans stored section text** instead of an FTS5 index (#187), with fast paths (#189), a
  parallel scan with exact pruning (#194) and a bounded background warm after open (#214, #229).
- **Open** does segmentation once (#200), resolves each PDF font encoding once per document (#215)
  and peaks lower on large PDFs (#225).

## Operations

- **Release build.** The release binary is a native `x86_64-unknown-linux-gnu` build from GitHub's
  `ubuntu-22.04` runner with a `GLIBC_2.35` floor — Ubuntu 22.04/24.04/26.04 and Debian 12. The musl
  route was dropped (it missed the EPUB single-client bar) and 20.04/Debian 11 are no longer targets
  (#278).
- **CI `Perf A/B`.** Base and head are built and measured interleaved on one runner; only a slowdown
  beyond the bar fails, and a large improvement is reported as `improved` instead of failing (#284,
  #290).
- **Usage log, off by default.** `READING_MCP_USAGE_LOG=on` writes one JSON line per `tools/call`
  with fixed fields only — no document text, query, path or handle checksum — rotates daily and is
  summarised by `scripts/usage-summary.py` (#289).
- **Dead workflows removed.** Seven one-off measurement workflows (#279), and the obsolete
  deploy-tunnel workflow and script (#281).
- **Cache hygiene.** Interrupted raw-cache temp files are removed at startup and the raw cache is
  capped by LRU eviction (#280); a bounded startup prune drops stale open results and unreferenced
  documents (#230).

## Upgrade notes

### Version constants that moved

| constant | `v0.4.11` | this release | moved by |
| --- | --- | --- | --- |
| `TEXT_UNIT_STORE_VERSION` | absent | `text-unit-store/v13` | #228 (`v11`), #247 (`v12`), #256 (`v13`) |
| `PDF_TEXT_EXTRACTION_VERSION` | absent | `pdf-text-extraction/v7` | #212 (`v1`), #224 (`v2`), #237 (`v3`), #252 (`v4`), #254 (`v5`), #263 (`v6`), #285 (`v7`) |
| `LEXICAL_SEARCH_INDEX_VERSION` | `lexical-search-index/v4` | `lexical-scan/v1` | #187 |
| `OPEN_RESULT_VERSION` | absent | `open-result/v1` | #173 |
| `TEXT_UNIT_STREAM_VERSION` | absent | `text-unit-stream/v1` | #174 |
| `NORMALIZATION_VERSION` | `reading-mcp-normalization/v11` | unchanged | — |
| `TEXT_SEGMENTATION_VERSION` | `text-segmentation/v3` | unchanged | a pending D2 bump, not merged |

**What this re-ingests.** The open-result fingerprint covers all of the above, so every stored
document re-ingests once on its first open after the upgrade, and PDFs also miss the parsed cache.
Nothing that cannot be rebuilt is touched: canonical documents, the raw cache and the open-result
store survive, only derived indexes and open results are rewritten.

**Old handles and locators.** A `TextLocator` minted at `v0.4.11` keeps its identity fields —
`document_id`, the content hash, `NORMALIZATION_VERSION` and `TEXT_SEGMENTATION_VERSION` did not
move — so its values remain valid citation identities, but no v2 tool accepts a locator as input:
`cite` returns one and everything else takes a handle. A v2 handle minted before the upgrade
answers `stale_handle` with a `retry` pointing at the current handle when the text is provably
unchanged (#283, #285).

### Environment variables added

| variable | default | what it does |
| --- | --- | --- |
| `READING_MCP_TOOLS` | `v2` | tool set; `v2` is now the only accepted value (#203, #269) |
| `READING_MCP_READ_POOL` | `4` (max `16`, `0` off) | read-only connections per store (#286) |
| `READING_MCP_RAW_CACHE_MIB` | `1024` (`0` = no cap) | raw URL-body cache cap with LRU eviction (#280) |
| `READING_MCP_SOURCE_VIEW_CACHE_MIB` | `256` (`0` off) | rendered-page disk cache (#277) |
| `READING_MCP_SOURCE_VIEW_FORMAT` | `auto` | `auto` = JPEG for raster-dominated pages, `png` = PNG only (#277) |
| `READING_MCP_SEARCH_CACHE_MIB` | `48` (`0` off) | per-document section-text cache for the scan (#194) |
| `READING_MCP_SEARCH_THREADS` | `min(cores, 4)` | scan threads for documents of 1 MiB and more (#194) |
| `READING_MCP_SCAN_PREWARM` | `1` | warm the scan cache in the background after open (#214, #229) |
| `READING_MCP_RESOLVE_LANDING_PAGES` | `1` | resolve a paper landing page to its PDF (#216) |
| `READING_MCP_USAGE_LOG` | `off` | one JSON line per tool call (#289) |
| `READING_MCP_USAGE_LOG_DAYS` | `30` | usage-log retention (#289) |

No `READING_MCP_*` variable was removed. Two values changed meaning:

- `READING_MCP_TOOLS=v1` and `=both` are startup errors now (#269); unset or `v2` serves the seven
  v2 tools.
- `READING_MCP_STATE_DIR=memory` still uses the same SQLite and file caches, in a temporary
  directory that is deleted when the server exits (#169).

### Removed

- The nine v1 tools: `open_document`, `get_document_structure`, `get_text_units`, `read_document`,
  `search_document`, `get_context`, `get_source_view`, `list_documents`, `list_directory` (#269).
- The v1-only env values `READING_MCP_TOOLS=v1` and `=both` (#269).
- The in-memory state mode (#169), the non-PDF parsed cache (#193), the FTS5 search index (#187) and
  the decoded-document cache (#209).

## Known limits

- **Scanned PDFs need OCR, and OCR is not deployed.** With OCR off (the default) an image-only PDF is
  a clear `ocr_required` with its page and character counts, not readable text (#224).
- **Fonts, option C is skipped.** Options A and B ship (#245 and the pending `cmf1`); extending the
  built-in program-encoding path to CFF/TrueType programs was measured at ≤151 characters in 3
  papers and would change the decode path of 98 papers' Latin fonts
  ([`pdf-open-time-and-cmap.md`](../design/pdf-open-time-and-cmap.md) §4).
- **Page furniture.** 45 header/footer lines in 30 of 121 papers still reach the reader as their own
  text, 4 952 one-character units remain (dot leaders, maths ellipses), and 92.4 % of units longer
  than 800 characters are whole paragraphs the guard refused to split
  ([`pdf6a-text-quality.md`](../design/pdf6a-text-quality.md), #233).
- **The PDF layout backend is not established.** It refused 4 of 5 CJK papers, so every number here
  is the default backend ([`pdf7a-layout-backend-data.md`](../design/pdf7a-layout-backend-data.md),
  #238).
- **Very large single sections.** A 64 MiB single section is skipped by the bounded search warm, so
  its first search stays around 850 ms, and it still misses its memory bound (#229, #225).
- **The PDF corpora are arXiv-only** (121 CC-BY/CC-BY-SA/CC0 papers): no scans, no other publishers,
  no CJK books.
