owners, and STOP before enumerating the next canonical owner's body.

- `tests/named_section_boundary_mcp.rs` — the same boundary through the MCP
  surface.
- `tests/raft_named_section_evidence.rs` — real canonical Raft 2014 PDF:
  `EVIDENCE_ABSTRACT`/`EVIDENCE_BC` show structure-only resolution producing
  executable intervals and the next owner (`1 Introduction`,
  `next_body_order=2`); `EVIDENCE_ABSTRACT_BODY`/`EVIDENCE_D` prove only the
  explicitly allowed bodies were revealed.
- Exact-read scoping: `tests/precise_read_locator.rs` /
  `precise_read_locator_review.rs` / `precise_read_locator_stdio.rs` (9 tests)
  prove `read_document` returns exactly the locator-bounded text slice —

## Item 12 — Deployment target + rollback evidence

Deployment target (from `deploy/systemd/reading-mcp-tunnel.service`,
`scripts/install-production.sh`): systemd service `reading-mcp-tunnel.service`
running the stable `reading-mcp` symlink inside a versioned binary directory
(`RELEASE_BIN_DIR/reading-mcp-<SHA>`), with `ENV_FILE`, `STATE_DIR`, and the
`tunnel-client` profile (`TUNNEL_PROFILE_DIR`/`TUNNEL_PROFILE`) provisioned
separately. `install-production.sh` templates the unit, keeps a
`.previous` copy under `deploy-rollback/`, and enables (does not start) the
service.

Deploy path (`scripts/deploy-production.sh`, requires root): verifies
`SHA256SUMS` + `EXPECTED_ARCHIVE_SHA256` before extraction, rejects non-file/
non-directory or path-escaping archive entries, cross-checks
`release-manifest.json` (version, git_sha, target, platform, binary sha)
against all `EXPECTED_*` inputs, snapshots `STATE_DIR` + the installed unit +
identity checksums into a `$ROLLBACK_DIR/<ts>-<sha>` checkpoint, installs
`reading-mcp-<EXPECTED_SHA>` next to the retained rollback binary (whose
sha256 must equal `ROLLBACK_BINARY_SHA256`), flips the `reading-mcp` symlink,
restarts, and requires `systemctl is-active` — failure explicitly instructs
rollback.

Rollback (`scripts/rollback-production.sh`): `ln -sfn` back to the retained
`reading-mcp-$ROLLBACK_SHA` (must exist and be executable), daemon-reload,
restart, active check. Canonical state is preserved; the deploy checkpoint
retains the state tarball and prior unit for manual state restore.

Verification (`scripts/verify-production.sh`): service active, symlink target
matches `EXPECTED_SHA`, binary sha256 matches the release manifest, `STATE_DIR`
accessible, `tunnel-client doctor` passes, and a journald scan fails the check
if recent logs match the secret/body redaction guard.

Evidence now: script env contracts, archive/manifest verification chain,
retained-binary requirement, symlink-swap mechanism, and the dry-run artifact
from Item 11 is exactly the input `deploy-production.sh` consumes.
NOT_RUN: actual install/deploy/rollback against a production unit — frozen by
#137 and requires root plus real tunnel credentials.
